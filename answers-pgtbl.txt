CS311 Assignment 03, Task 1 -- Page Tables

Evidence: test-results/starter.txt, test-results/pgtbltest.txt and
test-results/pgtblextra.txt. Addresses below are observed values, not the
illustrative addresses on the lab page. Physical allocations may vary on rerun.

1. Inspect a user-process page table

The original starter printed these nonzero entries:
VA             PTE          PA          flags   contents
0x0            0x21fc885b   0x87f22000  0x5b    executable text/rodata
0x1000         0x21fc7c17   0x87f1f000  0x17    data and BSS
0x2000         0x21fc7807   0x87f1e000  0x07    stack guard
0x3000         0x21fc74d7   0x87f1d000  0xd7    user stack
0x3fffffe000   0x21fd08c7   0x87f42000  0xc7    trapframe
0x3ffffff000   0x2000184b   0x80006000  0x4b    trampoline

All other entries printed by the starter were zero: VA 0x4000, 0x5000,
0x6000, 0x7000, 0x8000, 0x9000, and the high-address sample pages
from 0x3fffff6000 through 0x3fffffd000 inclusive (eight pages).
These are unmapped, not mappings to physical page zero. USYSCALL is the
last of those eight pages and was not implemented in the starter.

The final implementation's sampled mappings are:
VA             PTE          PA          flags   contents
0x0            0x21fdf85b   0x87f7e000  0x5b    executable text/rodata
0x1000         0x21fdec17   0x87f7b000  0x17    data and BSS
0x2000         0x21fde807   0x87f7a000  0x07    stack guard
0x3000         0x21fde4d7   0x87f79000  0xd7    user stack
0x3fffffd000   0x21fec413   0x87fb1000  0x13    USYSCALL (PID)
0x3fffffe000   0x21fe7cc7   0x87f9f000  0xc7    trapframe
0x3ffffff000   0x20001c4b   0x80007000  0x4b    trampoline

The other thirteen sampled final entries are zero: the six low pages
0x4000 through 0x9000 and seven high pages 0x3fffff6000 through
0x3fffffc000. These are holes above the current program and below USYSCALL.
Heap allocations in pgaccess_test occur later, after this inspection.

The executable's actual ELF LOAD headers place text/rodata at 0x0,
filesz/memsz 0xfc1, R E; and data at 0x1000, filesz 0x10, memsz 0x30,
RW. kernel/exec.c rounds the image up and adds a guard and one stack page,
which identifies 0x2000 and 0x3000 respectively. The stack holds function
frames and the initial argc/argv data. proc_pagetable installs the high
special mappings; their addresses are defined in kernel/memlayout.h.

PTE flags: V=bit 0, R=1, W=2, X=3, U=4, G=5, A=6, D=7.
V permits translation; R/W/X govern reads/writes/instruction fetches;
U allows user-mode access. A records accesses (including instruction
fetches); D records writes. Neither A nor D grants access permission.
Thus 0x5b is V/R/X/U/A; 0x17 is V/R/W/U; 0x07 is V/R/W;
0xd7 is V/R/W/U/A/D; 0x13 is V/R/U; 0xc7 is V/R/W/A/D;
and 0x4b is V/R/X/A. No displayed mapping is both writable and executable.
The guard and trapframe exclude users via U=0; the trampoline is also
supervisor-only. USYSCALL permits user reads but neither writes nor execution.

A normal Sv39 PTE stores its physical page number in bits 53:10; bits
9:0 contain flags/software bits. The code extracts the page base with
PTE2PA(pte). For a 4 KiB leaf, add the low 12 bits of the virtual address
to obtain a byte's physical address. For example, final VA 0x3008 maps
to 0x87f79008. A virtual address identifies a location in this process's
address space; its physical address identifies the actual memory location.

kalloc removes individual pages from a free list. Page-table allocations
and previous process activity interleave with user-page allocations, so
adjacent virtual pages do not require adjacent physical pages. The gap
between the observed text and data physical pages is an example.

2. Walk and print

Despite the lab section's 'two-level' heading, this starter uses Sv39:
levels 2, 1 and 0, with 512 eight-byte entries per table. PXSHIFT selects
VA bits 38:30, 29:21 and 20:12 respectively. vmprintlevel accumulates the
indices into a complete virtual base address. One, two and three ' ..'
prefixes identify entries in those levels. A valid entry without R/W/X
points to a child table; an entry with leaf permissions terminates traversal.

The final root printed at 0x87f81000 has entries covering virtual bases
0 and 0x3fc0000000. Their children cover bases 0 and 0x3fffe00000.
The seven leaves printed are precisely the seven nonzero final entries
listed above, with the same PTEs and physical addresses:
  0: RXU, program instructions/constants, no user writes.
  0x1000: RWU, mutable globals/BSS, no execution.
  0x2000: RW, guard, no user access or execution.
  0x3000: RWU, stack, no execution.
  USYSCALL: RU, PID, no user writes or execution.
  TRAPFRAME: RW, saved registers, no user access or execution.
  TRAMPOLINE: RX, trap entry/return code, no writes or user access.
Intermediate entries have only V set and are not data mappings.
Invalid entries are omitted. vmprint labels an upper-level leaf 'superpage'
and does not treat its mapped memory as another page table.

pgaccess accepts 1..4096 pages and a potentially unaligned starting address.
It writes ceil(npages/8) bytes, putting page i in bit i%8 of byte i/8.
It validates the entire source and output before consuming access history.
The successful scan clears A so the next scan reports later activity.
Translation caches must not retain an old accessed state: sfence_vma and
the existing trampoline fences ensure subsequent user translations observe
the cleared PTE. xv6 has no concurrent threads sharing this process's table.
The output may overlap scanned memory; copyout uses the kernel direct map.

3. Other system calls suitable for shared information

uptime could read a kernel-maintained tick count from a read-only shared
page, updated by the timer handler. A global shared tick page avoids updating
one copy for every process on every tick. Data wider than an atomic load or
multiple related fields would need a version/retry protocol for consistency.
getpid is especially simple because the PID is immutable for the process:
allocproc writes it once; fork gets a fresh page containing the child's PID;
exec maps the same process-owned page in the replacement page table.
User code reads it directly instead of executing ecall and returning through
the kernel's syscall path. Calls that perform I/O or change protected state
cannot generally be replaced by merely reading shared information.

4. Kernel superpage count and savings

ksupernpte observed 95 superpage leaves and 579 ordinary leaves.
The linked kernel has etext=0x80008000. kvmmake's eligible mappings are:
  PLIC: 0x0c000000..0x10000000, 64 MiB / 2 MiB = 32 superpages.
  RAM: 0x80200000..0x88000000, 126 MiB / 2 MiB = 63 superpages.
Total = 32 + 63 = 95. All are aligned in VA and PA and retain RW permissions.
The kernel text and the first partial RAM region remain ordinary pages,
preserving the RX/RW boundary at etext. UART, virtio, trampoline and kernel
stacks also retain ordinary pages. No user superpages are created.

Each 2 MiB mapping replaces 2 MiB / 4096 = 512 ordinary leaf mappings.
95 * 512 = 48,640 bottom-level leaf mappings are replaced, eliminating
95 bottom-level page-table pages. Table storage saved is 95 * 4096 =
389,120 bytes = 380 KiB. The RAM/MMIO being mapped is not eliminated.
Net reduction in leaf-entry count is 48,640 - 95 = 48,545.
The 579 retained ordinary leaves are 512 for the first 2 MiB of RAM
(8 RX text pages and 504 RW pages), 64 kernel stacks, 2 device pages and
1 trampoline. Check: 48,640 + 579 = 49,219 original ordinary mappings.
